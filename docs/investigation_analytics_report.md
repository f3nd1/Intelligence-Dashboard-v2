## 1. Data Flow

### 1.1 What is on the page before any JS runs

`custom-html-block/HTML.html` is a **single line 1** wrapper `<div class="ucc-platform" data-build-id="UCC-PLATFORM-2.0.1-SHARED" data-platform-version="2.0.1" id="uccIntelligencePlatform">` containing three workspace `<section>`s. Analytics is `HTML.html:5` — `<section class="ucc-platform-workspace" data-ucc-workspace-panel="analytics">`.

Inside it (`HTML.html:6`) are **seven empty `<div>` mount points**, one per criterion:

```html
<div class="ucc-criterion-dashboard" data-dashboard-architecture="shared-v2"
     data-dashboard-panel="criterion_5" data-demo-active-tab="overview"
     data-demo-dashboard="criterion_5"></div>
```

Verified detail: they are **completely empty** — no chart markup, no tabs, no cards ship in the HTML. All Analytics DOM is generated by JS. Criterion 5 is the only one without `ucc-hidden`, i.e. the default visible panel; it is also the `selected` option in the dashboard `<select>` at `HTML.html:5` (`#uccDashboardSelect`).

Observation: criteria 1, 2, 3, 6, 7 carry `data-live-api="1"` in the static HTML; **criteria 4 and 5 do not** (`HTML.html:6`). This attribute is set unconditionally for every mounted dashboard later at `JAVASCRIPT.js:2662`, so the static difference has no runtime effect I can find — it appears to be a leftover from the era when only 1/2/3/6/7 were "live foundations" (matches `VERSION.json` → `implemented.live_api_foundations`, which lists exactly those five).

### 1.2 Initial load trigger

`custom-html-block/JAVASCRIPT.js:2144` opens the IIFE `/* UCC unified dashboard engine v2.0.1 */`. Entry sequence:

| Step | Location | Behaviour |
|---|---|---|
| Root lookup | `JAVASCRIPT.js:2147` | `typeof root_element!=="undefined" ? root_element.querySelector("#uccIntelligencePlatform") : document.querySelector(...)` — `root_element` is the Frappe Custom HTML Block injected variable |
| Re-entry guard | `JAVASCRIPT.js:2148-2149` | bails if `platform.dataset.liveFoundationReady==="1"`, then sets it |
| Access gate | `JAVASCRIPT.js:2691` | `fetchDashboardAccess().then(...)` → `applyDashboardAccess(access)` → **then** `bootstrapDashboards()` |
| Mount | `JAVASCRIPT.js:2661` | `mountUnifiedDashboards()` |
| First fetch | `JAVASCRIPT.js:2662` (end) | `if(!dashboard.classList.contains("ucc-hidden")) loadLive(dashboard); else renderReadiness(dashboard,config,null)` |

**There is no `DOMContentLoaded` listener for Analytics.** The only one in the file is `JAVASCRIPT.js:247`, which belongs to the shared runtime/shell. The Analytics engine runs immediately on script evaluation.

**The access gate is a real `frappe.call`** (`JAVASCRIPT.js:2613`) to method `ucc_dashboard_access`, args `{}`. It is deliberately fail-open: an 8-second timeout at `JAVASCRIPT.js:2609` resolves `null`, and `applyDashboardAccess` returns `{applied:"fail_open",...}` on null (`JAVASCRIPT.js:2629`). When access *is* returned, hidden criteria are removed from the DOM **and** deleted from `CONFIG` before mounting (`JAVASCRIPT.js:2633-2638`), so a hidden criterion's tab bar is never constructed. The in-code comment at `JAVASCRIPT.js:2599-2602` states this is interface composition only and that every data call keeps its own permission check.

**Net effect: only ONE criterion fetches on load** — the one not carrying `ucc-hidden` (Criterion 5 by default). The other six mount their DOM shell and call `renderReadiness(dashboard, config, null)` with a null result.

### 1.3 The frappe.call

Single function, `callApi` at **`JAVASCRIPT.js:2332-2361`**:

```js
function callApi(config,dashboard,action="summary",extra={}){
 return new Promise((resolve,reject)=>{
  if(!(window.frappe&&frappe.call)){reject(new Error("Frappe API client is unavailable."));return;}
  const payload={action,subcriterion:apiSection(config,dashboard,activeSection(dashboard)),
                 filters:selectedFilterObject(dashboard),page_size:100};
  Object.keys(extra||{}).forEach(key=>payload[key]=extra[key]);
  logEvent(dashboard,"INFO","api_request",`${config.apiMethod} · ${payload.subcriterion} · ${action}`);
  frappe.call({
   method:config.apiMethod,
   args:{payload:JSON.stringify(payload)},
   callback(response){ ... },
   error(error){ ... }
  });
 });
}
```

Key facts:
- **The entire request is one JSON string** in a single arg named `payload`. Not individual args.
- `config.apiMethod` values (extracted from the `CONFIG` literal at `JAVASCRIPT.js:2151`) are exactly `ucc_analytics_criterion_1` … `ucc_analytics_criterion_7` — a 1:1 map to the seven Server Scripts.
- Default `action` is `"summary"`; `page_size` is hardcoded `100`.
- `filters` comes from `selectedFilterObject` (`JAVASCRIPT.js:2231`), which reads every `[data-demo-filter]` input in that dashboard and includes only non-empty values.
- `subcriterion` comes from `apiSection` (`JAVASCRIPT.js:2232`): for tabs `quality` and `sources` it returns `state.lastSection||config.defaultSection` — i.e. **the Sources & Data Quality tab does not fetch its own section**, it reuses whatever analytical section was last loaded.

`config.apiSections` per criterion (from the `CONFIG` literal, `JAVASCRIPT.js:2151`):

| 2 | overview→2.1.1, 2.1.1, 2.1.2, 2.2.1, 2.3.1, 2.3.2, 2.4.1, 2.4.2, 2.4.3 | 2.1.1 |

### 1.4 Response handling

`callback` (`JAVASCRIPT.js:2341-2352`) runs three stages:

1. **`normaliseApiMessage(response)`** — `JAVASCRIPT.js:2197`. Unwraps `response.message`, then loops up to **3 times** attempting `JSON.parse` if the value is still a string. Defends against double/triple-encoded payloads.
2. **`adaptApiResponse(config,dashboard,payload,rawMessage)`** — `JAVASCRIPT.js:2326`. Looks up `RESPONSE_ADAPTERS` by criterion id, falling back to `baseResponseAdapter` (`JAVASCRIPT.js:2323`). Only **one** criterion registers a custom adapter: `registerResponseAdapter("criterion_4",...)` at `JAVASCRIPT.js:2325`, which back-fills `questions` from `message.management_questions`.
3. **Contract check** — resolves only `if(message&&message.ok)`. Otherwise rejects with `message.message` or the literal `"Analytics response did not contain ok=true."`.

Every request and outcome is appended to a per-dashboard ring buffer by `logEvent` (`JAVASCRIPT.js:2229`), capped at 500 entries, surfaced through `showDiagnostics` (`JAVASCRIPT.js:2596`).

### 1.5 loadLive — the caching layer

**`JAVASCRIPT.js:2570`**:

```js
async function loadLive(dashboard,force=false){
 const config=CONFIG[...],state=dashboardState(dashboard),
       section=apiSection(config,dashboard,activeSection(dashboard));
 ensureLiveSectionCards(dashboard,config,activeSection(dashboard));
 if(state.loading)return;
 if(!force&&state.result&&state.result.meta?.subcriterion===section){renderDashboard(dashboard);return;}
 ...
}
```

- Per-dashboard state lives in a `Map` keyed by DOM node: `STATE`/`dashboardState` (`JAVASCRIPT.js:2227-2228`), shape `{loading,result,error,logs,lastSection}`.
- **Cache key is `result.meta.subcriterion` compared against the computed section.** Only one result is cached per dashboard — switching subcriterion always refetches, and switching back refetches again.
- In-flight guard is `state.loading`.
- Progress overlay is driven at 15% → 80% → 100% (`JAVASCRIPT.js:2570`), cleared 150 ms after completion.
- On error: `state.error` is set, `renderDashboard` still runs (so `renderError` can paint), overlay cleared.

### 1.6 Tab switching

Wired in `bootstrapDashboards` (`JAVASCRIPT.js:2662`):
`dashboard.querySelectorAll("[data-demo-tab]").forEach(button=>button.addEventListener("click",()=>showTab(dashboard,button.dataset.demoTab)))`

`showTab` (**`JAVASCRIPT.js:2571`**) does, in order: set `dataset.demoActiveTab` → toggle `.active` on tab buttons → resolve `panelKey` via `config.panelMap` → toggle `.hidden` on `[data-demo-panel]` → `ensureLiveSectionCards` → `syncLiveSectionVisibility` → **`if(tab!=="quality"&&tab!=="sources") loadLive(dashboard); else renderDashboard(dashboard)`**.

So Sources & Data Quality renders from cache and never triggers a fetch.

Filter changes force a refetch: `input.addEventListener("change",()=>loadLive(dashboard,true))` (`JAVASCRIPT.js:2662`).

Criterion switching is event-driven: `platform.addEventListener("ucc:dashboard-change", ...)` at `JAVASCRIPT.js:2662` (end) calls `loadLive` on the newly selected dashboard. The dispatcher for that event is in the shell code above line 2144 and I did not trace it — **unverified**.

### 1.7 Lazy / click-to-render (two distinct mechanisms)

**(a) Card DOM is created per section, on demand.** `ensureLiveSectionCards(dashboard,config,sectionKey)` (**`JAVASCRIPT.js:2241`**) creates a `<div class="grid2 ucc-live-expanded-grid" data-live-section="...">` inside the panel and fills it once, guarded by `grid.dataset.liveCardsMounted`. Cards are filtered by `chart.enabled!==false` (`JAVASCRIPT.js:2257`) — this is the archived-visual mechanism described in `VERSION.json.notes`. Insert position is computed by `panelInsertPoint` (`JAVASCRIPT.js:2238`), which finds the child whose text matches `/Management Questions and Data-Based Answers/i` — a **text-matching DOM anchor**, noted as fragile.

**(b) Charts are deferred until visible/clicked.** This is a two-function split:

- `renderLiveChartCard(dashboard, chart, index, result)` — **`JAVASCRIPT.js:2462`**. Sets the card's `h2` and `.ucc-card-description`, stashes `card._liveCardPending = {chart,index,result}`, sets `card.dataset.liveCardRendered = ""` (empty). **It does not draw anything.**
- `renderLiveChartCardNow(card)` — **`JAVASCRIPT.js:2491`**. Returns immediately unless `_liveCardPending` exists and `dataset.liveCardRendered!=="1"`. Computes rows via `metricRows`, calls `chartForLive` for the SVG/HTML, fills the table `<tbody>`, then sets `liveCardRendered="1"` — a **permanent per-card cache**.

`renderDashboard` (`JAVASCRIPT.js:2569`) calls `renderLiveChartCard` for every definition (cheap, metadata only), then calls `renderLiveChartCardNow` **only** for `[data-live-section="<activeTab>"] [data-demo-card]` — i.e. only the visible section's cards draw.

The Diagram/Table toggle also forces a draw: the click handler at `JAVASCRIPT.js:2662` calls `renderLiveChartCardNow(card)` before toggling `.hidden` on `[data-demo-chart]` / `[data-demo-chart-table]`.

Observation: because `liveCardRendered` is only ever set to `"1"` or `""`, and `renderLiveChartCard` resets it to `""` on each `renderDashboard`, a re-render after a refetch correctly re-enables drawing. Verified by reading; not executed.

## 2. Server Script Architecture

Seven files, `server-scripts/UCC Analytics - Criterion 1.py` … `7.py`, 1,827–3,398 lines each. All are Frappe **Script type: API**, method names `ucc_analytics_criterion_N`, and every docstring states `Allow Guest must remain disabled` (e.g. `Criterion 5.py:19`).

These are **top-level scripts, not modules** — no `def main()`, no `@frappe.whitelist()`. They execute top-to-bottom in Frappe's `safe_exec` sandbox and terminate with `frappe.response["message"] = result` (`Criterion 5.py:3398`).

### 2.1 Common skeleton (all 7)

| Stage | Example (Criterion 5) | Notes |
|---|---|---|
| Payload parse | `C5.py:22-28` | `frappe.form_dict.get("payload")`, `json.loads` if str, coerce non-dict → `{}` |
| Param extraction | `C5.py:30-37` | `action`, `subcriterion`, `filters`, `metric_id`, `question_id`, `page`, `page_size`, `limit` |
| Bounds clamping | `C5.py:39-51` | `page≥1`; `page_size` clamped to **1–200**; `row_limit` clamped to **1–2000** |
| Action allowlist | `C5.py:53-58` | `ALLOWED_ACTIONS`, else `frappe.throw` |
| Registries | `C5.py:64,301,842` | see §2.2 |
| Helper layer | `C5.py:2222-2340` | `clean_text`, `lower_text`, `is_truthy`, `to_number`, `is_permission_error`, `get_meta`, `field_exists`, `resolve_field`, `safe_fields`, `applied_filters` |

### 2.2 The registry pattern

**`POLICY_REGISTRY`** — present in all 7 (`C1:63`, `C2:63`, `C3:81`, `C4:66`, `C5:64`, `C6:61`, `C7:63`). Keyed by subcriterion code, carries the controlling policy document reference. `VERSION.json.policy_registries` lists the document codes (e.g. `PPD-SGL-CG-1.1.1 v2.2`); note it has **no entry for criterion_4 or criterion_5** even though both files define a `POLICY_REGISTRY`.

**`SOURCE_CANDIDATES`** — all 7 (`C5:103`). Maps an internal alias to an **ordered list** of candidate DocType names, e.g. `{'course_proposal': ['Course Proposal'], ...}`. The ordering enables fallback resolution.

**`SAFE_FIELDS`** — all 7 (`C5:145`). Per-alias field allowlist. Combined with `STANDARD_FIELDS` (`C5:2203`) and filtered through `safe_fields(doctype,fields)` (`C5:2312`) so only fields that actually exist on the resolved DocType are requested.

**`QUESTION_REGISTRY`** — all 7 (`C1:595`, `C2:887`, `C3:957`, `C4:1020`, `C5:842`, `C6:581`, `C7:554`). Keyed by section. Criterion 5's entries are the richest, carrying `management_purpose`, `why_useful`, `requirement_reference`, `calculation`, `primary_source`, `source_keys`, `support_status` (`C5:842-852`). Criterion 2's are minimal — `{'id','question','metric_id'}` only (`C2:887`).

**Metric configuration — this is where the criteria structurally diverge:**

- **Criteria 1, 2, 3, 4, 6, 7** use a single **`CONFIG`** dict keyed by section, each holding `{"sources":[...], "metrics":[...]}` (`C1:167`, `C2:435`, `C3:238`, `C4:323`, `C6:225`, `C7:161`).

### 2.4 Evidence-status state machine

```python
                       limit_page_length=1, order_by="modified desc") or []
```

| Status | Set when | Line (C5) |
|---|---|---|
| `checking` | initial attempt state | `:2348` |
| `available` | `frappe.get_list` returned | `:2358` |
| `permission_denied` | exception **and** `is_permission_error(error)` | `:2386` |

### 2.5 The shared response contract

`standardise_response_contract(result, criterion_name, api_method, action_name, subcriterion_name, row_limit_value)` — present in all 7 (`C1:1568`, `C2:1555`, `C3:1986`, `C5:3226`, `C6:1919`, `C7:1800`). Read in full at `C5:3226-3292`.

It guarantees:
- `result["ok"]` is a bool (defaults **`True`**)
- `result["meta"]` carries `api_method`, `criterion`, **`contract_version":"2.1.0"`**, `action`, `subcriterion`, `row_limit`
- 14 keys are coerced to lists if absent or wrong-typed: `resolved_filters, unresolved_filters, sources, source_mapping, metrics, supporting_metrics, questions, requirements, exceptions, evidence_gaps, data_quality, warnings` (plus back-fills)
- `requirements` back-fills from `requirement_evidence`
- `supporting_metrics` back-fills by filtering `metrics` for `category=="supporting"`
- `source_mapping` is synthesised from `sources` when absent

**Criterion 5 calls it twice** — once at `C5:3315` before the action branch, and again at `C5:3396` after it. Reading the code, the second call re-normalises keys the action branch added (`registry`, `drilldown`, `source_status`). Verified as intentional-looking, not confirmed.

**Observation — `meta.subcriterion` is rewritten.** C5's raw result sets `meta.subcriterion = requested_subcriterion` (`C5:3303`) and `meta.canonical_subcriterion = canonical_subcriterion` (`C5:3304`), but `standardise_response_contract` overwrites `meta["subcriterion"]` with the **canonical** value it was passed (`C5:3241`, called with `canonical_subcriterion` at `C5:3315`).

This interacts with the frontend cache check. `SUBCRITERION_ALIASES = {"5.4":"5.4.1","5.5":"5.5.1"}` (`C5:61`), while the frontend's `apiSections` maps `"5.4"→"5.4"` and `"5.5"→"5.5"`. `loadLive`'s guard is `state.result.meta?.subcriterion===section` (`JAVASCRIPT.js:2570`) — so for tabs **5.4 and 5.5** the returned `"5.4.1"` never equals the computed `"5.4"`, and **those two tabs re-fetch on every visit**. Derived by reading both sides; not observed at runtime.

#### The shared rendering engine

**Chart plugin registry** — `CHART_PLUGINS = new Map()` (`:2298`), `registerChartPlugin(type,renderer)` (`:2299`), exposed as `window.UCCChartPlugins` (`:2317`). **16 types registered** at `:2300-2315`:

`bar`, `donut`, `funnel`, `lifecycle`, `flow` (aliases `lifecycle`), `matrix`, `radar`, `trend`, `gauge`, `admission-line`, `admission-column`, `decision`, `network`, `reconciliation`, `ladder`, `risk-matrix`.

Dispatch is `renderChart(node,chart,rows)` (`:2316`) — `CHART_PLUGINS.get(type) || CHART_PLUGINS.get("bar")`, so an unknown type silently degrades to a bar chart.

Renderers are hand-written HTML/inline-SVG string builders (`:2265-2297`). `renderRadar` and `renderTrend` emit `<svg viewBox>` with computed polygon/polyline points; `renderBars`, `renderDonut` (CSS `conic-gradient`), `renderFunnel`, `renderMatrix`, `renderLifecycle` emit div structures. **No charting library and no D3 in the deployed file** — `grep -c 'd3\.'` on `custom-html-block/JAVASCRIPT.js` returns **0**.

**Uniform card layout** — one template, `liveChartCardMarkup(chart)` (**`:2235`**):

```html

                ucc-standard-functional-card" data-demo-card="{chart.id}">
  <div class="panel-head ucc-card-header">

       data-demo-chart-title="..." data-demo-chart-type="..."></div>
```

This is exactly the title + description + Diagram/Table toggle structure. The table is always built alongside the diagram — same `rows`, rendered as `<tr>` with `statusBadge(status)` in the third column (`:2491`).

**Dashboard shell** — `dashboardShellMarkup(criterionId,config)` (`:2181`) composes: loading overlay with progress track → hero → filters (`filterMarkup`, `:2158`) → tab bar → panels. Tabs are `[['overview','Overview']] + config.subcriteria + [['sources','Sources & Data Quality']]` (`:2178`). Panels come from `analyticsPanelMarkup` (`:2168`) plus `sourcesQualityPanelMarkup` (`:2172`).

**Data shaping** — `metricRows(result,chartIndex,chart)` (`:2399`) decides what a chart plots:
1. If `chart.dataKey` → `result.admission_intelligence.charts[dataKey]` (Criterion 4 only)
2. Else filter `result.metrics` to `status==="available"`
3. **Title-based special-casing**: `/source availability|evidence readiness|source readiness/` on the chart title returns synthesised rows from `source_summary`/`metric_summary` (`:2407-2410`)

**Failure ladder** — `chartForLive(node,chart,rows)` (`:2447-2461`), in order:
1. no rows + blocked sources → `UCCShared.permissionNoticeHtml`, sets `dataset.uccPermissionBlocked="1"`
2. no rows → "No live metric is readable for this section" + Source mapping report button
3. rows present but no finite numbers → "The returned metrics are not numeric" (explicitly "stopped before an invalid SVG path could be produced")
4. `renderChart` in try/catch → `dataset.visualRenderError` + diagnostic panel

**Public surface** — `window.UCCLiveAnalytics` (`:2702`), frozen, exposing `config`, `registerResponseAdapter`, `registerChartPlugin`, `refresh(criterion)`, `showTab(criterion,tab)`. Also `window.UCCLiveVisualDefinitions = LIVE_VISUAL_EXPANSION` (`:2153`).

#### Chart definitions

`LIVE_VISUAL_EXPANSION` (`:2152`) holds the per-criterion, per-section chart definitions — `{id,title,type,description,i}`, plus `enabled:false` for archived visuals. It is **merged into `CONFIG.sections` at load** (`:2154`), creating the section if absent. So `CONFIG` declares API wiring while `LIVE_VISUAL_EXPANSION` declares visuals.

### 3.4 How the three files interact

```
HTML.html  ──provides──► #uccIntelligencePlatform, 7× [data-dashboard-panel]
                                 │
JAVASCRIPT.js:2147 ──queries──► root_element (Frappe-injected) or document
JAVASCRIPT.js:2192 ──writes──► dashboard.innerHTML = dashboardShellMarkup(...)
JAVASCRIPT.js:2257 ──writes──► grid.innerHTML = liveChartCardMarkup(...)   [per section, once]
JAVASCRIPT.js:2491 ──writes──► chartNode.innerHTML (via CHART_PLUGINS)     [per card, once]
                                 │
CSS.css ──styles──► .ucc-demo-*, .ucc-live-*, .ucc-card-*, .ucc-plugin-*, .ucc-admission-*
                    (classes exist ONLY in JS template strings, never in HTML.html)
                                 │
JAVASCRIPT.js:2340 ──frappe.call──► ucc_analytics_criterion_N  (payload JSON string)
Server Script      ──frappe.response["message"]──► normaliseApiMessage → adaptApiResponse
```

The critical coupling: **every Analytics CSS class is emitted from a JS template literal, never from HTML.html.** HTML.html contributes only the shell and seven empty divs. A CSS rename therefore requires a JS change, and vice versa — nothing in the HTML pins them together.

### 4.1 `src/` is not the source of the deployed build — quantified

### 4.5 Criterion 5 tabs 5.4 and 5.5 defeat the result cache

`SUBCRITERION_ALIASES` (`C5:61`) canonicalises `5.4→5.4.1`, `5.5→5.5.1`, and `standardise_response_contract` writes the canonical value into `meta.subcriterion` (`C5:3241`). The frontend maps those tabs to themselves (`"5.4":"5.4"`) and caches on `meta.subcriterion===section` (`JAVASCRIPT.js:2570`). `"5.4.1" !== "5.4"` → the guard never holds → refetch on every visit. Derived from reading both sides; not observed running.

### 4.6 Two Server Scripts have no discoverable caller

`ucc_analytics_bootstrap` and `ucc_analytics_drilldown` are fully implemented with the same `payload` convention, but I found **no `frappe.call` to either** in the deployed `JAVASCRIPT.js`. The only Analytics-adjacent calls are `config.apiMethod` (`:2340`), `ucc_dashboard_access` (`:2613`) and `ucc_shared_diagnostics` (`:3199`). The UI's "View underlying records" button routes through `openRecords`/`openMetricRecords` (`:2662`), which I did not trace to its terminus — the drilldown may be served by the criterion scripts' own `action:"drilldown"` instead.

### 4.7 `data-live-api` in HTML is inert

Criteria 1, 2, 3, 6, 7 carry `data-live-api="1"` in `HTML.html:6`; 4 and 5 do not. `bootstrapDashboards` sets `dashboard.dataset.liveApi="1"` for every mounted dashboard (`:2662`), so the static distinction has no effect I can find.

### 4.8 Smaller observations (not defects, noted only)

- `panelInsertPoint` (`:2238`) locates its DOM anchor by regex-matching the string `Management Questions and Data-Based Answers` against `child.textContent`. Changing that heading text would silently relocate every generated chart grid.
- `metricRows` (`:2407`) special-cases charts by **regex on the human-readable title**. Retitling a chart to or away from "Source Availability" / "Evidence Readiness" / "Source Readiness" changes its data source.
- `renderChart` (`:2316`) falls back to `bar` for unknown types, so a typo'd `type` renders a plausible-looking wrong chart rather than failing.
- `standardise_response_contract` defaults `ok` to **`True`** (`C5:3231`). A script that fails before setting `ok` explicitly would still satisfy the frontend's `if(message&&message.ok)` gate (`:2345`).
- `normaliseApiMessage` (`:2197`) tolerates up to 3 levels of JSON string nesting — defensive, but implies double-encoding has been seen in practice.
- `partial` has no CSS rule (0 occurrences in `CSS.css`); it renders through `statusBadge`'s generic `warning` class (`:2234`).
- `VERSION.json.policy_registries` omits `criterion_4` and `criterion_5`, though both scripts define a `POLICY_REGISTRY`.
- Criterion 5 is the only script with module-level caches (`SOURCE_CACHE` et al., `C5:2215-2219`). In Frappe's `safe_exec` these live for one request only, so they are per-request memoisation, not cross-request state.
