## 9. Rollback for this phase

Phase 1 only ever touches a non-production site and adds a new app — it cannot corrupt existing data
by construction, which is itself one of the §9 exit criteria to verify, not assume.

- **If install fails partway**: `bench --site <site> uninstall-app ucc_intelligence` (§9 exit
  criterion — "App uninstalls without corrupting unrelated data" is exactly this path, must be
  tested, not just trusted).
- **If uninstall itself is incomplete or leaves residue**: restore the site from its pre-Phase-1
  backup. A backup before `install-app` is a prerequisite for this phase to be safe to run at all —
  add `bench --site <site> backup` as the actual first command, before `bench new-app`, once a site is
  named.
- **Git rollback**: revert the commit(s) this phase produces on `claude/init-0ih6io`. No production
  code path references the new app yet (nothing in `custom-html-block/` or `server-scripts/` is
  edited), so a git revert alone is sufficient on the code side — the only stateful risk is the
  installed site itself, covered above.
- **No irreversible action is taken in this phase.** No legacy file is edited, moved, or deleted; no
  production site is touched (§9 "development or staging first" is a hard constraint, not a
  preference).
